# Security Policy

## Supported versions

Security fixes are made on the current `main` branch and released in the latest published version. Older releases may not receive backports.

## Report a vulnerability privately

Do not open a public issue for a suspected vulnerability, leaked credential, private planning artifact, prompt-injection bypass, or supply-chain concern.

Use [GitHub private vulnerability reporting](https://github.com/mattlane66/planning-skills-for-agents-and-humans/security/advisories/new). If that form is unavailable, contact the repository owner through [their GitHub profile](https://github.com/mattlane66) without including sensitive details, and arrange a private channel.

Include the affected version or commit, impact, minimal reproduction, and any proposed mitigation. Remove unrelated personal or confidential data. You should receive an acknowledgement within seven days; disclosure timing will be coordinated after a fix or mitigation is available.

## Scope

Security-relevant reports include the MCP server, visualizer, packaging and release automation, dependency or action compromise, unsafe source handling, and instructions embedded in untrusted transcripts, issues, pages, files, or tool output that can bypass trusted user intent or human gates.
